# 02 UI 规范

> 标注说明：
> **【已确认】** 来自用户总指令，不得擅自修改。
> **【暂定】** 为实现需要先给出的具体数值，阶段 4/5 实施时需向用户确认后才能定稿。

> **实现状态（2026-11-13，阶段 4C-3）**：胶囊默认 320×104 DIP，四档统一按 320 : 104 等比例缩放：
> 迷你 220×71.5 / 小型 280×91 / 标准 320×104 / 大型 400×130；自定义范围 220–480 × 71.5–156，
> 比例不符时给中文提示。字号、圆角、内边距、图标与速度区随尺寸同步缩放，布局结构不变。
> 胶囊右键菜单固定为“流量统计（暂禁用）/ 固定或解除固定 / 调整大小… / 退出程序”，
> 设置入口只在系统托盘。设置窗口（780×620，深色三组卡片）已实现；统计窗口尚未实现。
> 胶囊与设置窗口的数值已落地并经自检坐标核对；统计窗口数值待实现时再确认。

## 0. 总原则

1. **两个独立窗口，永不合并**：悬浮状态栏（常驻、极简）与流量统计窗口（按需、完整）。
2. 悬浮窗只回答三个问题：连没连上？这次用了多少？现在多快？
3. 统计窗口才承担"日/周/月/历史"的完整性。
4. 任何新增信息都必须先判断"是否属于悬浮窗的职责"，不属于就放进统计窗口。

## 1. 悬浮状态栏

### 1.1 窗口形态【已确认】

- `WindowStyle=None`，无标题栏、无边框。
- 无关闭 / 最小化 / 最大化按钮。
- 无产品名称、无 Logo。
- 圆角胶囊外观。
- 可自由拖动；支持固定与解除固定。
- 记忆上次位置。
- 不在任务栏显示按钮（`ShowInTaskbar=False`）。
- 置顶显示（`Topmost=True`），但不抢焦点。

### 1.2 技术形态【暂定，阶段 4 验证】

| 项 | 方案 | 说明 |
| --- | --- | --- |
| 透明 | `AllowsTransparency=True` + `Background=Transparent` + `Border CornerRadius` | 最直观；但 WPF 分层窗口会走软件渲染，需实测 CPU/拖动流畅度 |
| 备选 | `WindowChrome` + 圆角 `Region` | 保留硬件加速，但抗锯齿边缘较差 |
| 尺寸 | 约 200×64 DIP（宽随内容自适应，最小 180） | 需实测"2.36 GB"与"↓ 2.4 MB/s ↑ 128 KB/s"是否放得下 |
| 圆角 | 外圆角 = 高度/2（胶囊形） | 固定值在 DPI 下按 DIP 计算 |
| 拖动 | `MouseLeftButtonDown` → `DragMove()`，仅未固定时 | `DragMove` 在鼠标已释放时会抛 `InvalidOperationException`，需捕获 |
| 固定 | 保存 `IsPinned=true` 与屏幕坐标；固定后不响应拖动 | 右键菜单可切换 |

### 1.3 视觉布局【已确认结构 + 暂定尺寸】

```
┌──────────────────────────────────────┐
│ 已使用流量                            │   ← 小字说明，在数字上方（65% 不透明度）
│ 2.36 GB                  ↓ 2.4 MB/s  │   ← 大字号会话流量／右侧竖排速度
│                          ↑ 128 KB/s  │
└──────────────────────────────────────┘
```

> 上图为当前实现（4C-11/4C-12，320×104）；1.3 早期的"图标 + 连接状态 / 速度右下角"方案已被
> 4C-8 精简设计取代，保留此注以免与历史描述混淆。

- **左上**：当前实现不显示 Wi-Fi 图标与连接状态文字，连接状态只由胶囊底色表达（4C-8 决定）。
- **右上**：当前会话已用流量，大字号（【暂定】28–32 px），是整块视觉焦点。
- **数字上方**："已使用流量"小字（10–11 px，`TextSecondary #A1A1A6`，`Opacity=0.65` 加在标签自身），与数字同字体家族、同字重、左边缘对齐。阶段 4C-10 起固定在数字上方，4C-11 起改为左对齐，4C-12 起降低标签不透明度；此前版本在下方且居中。
- **右下**：`↓ 下载速度` 与 `↑ 上传速度`，小字（【暂定】10–11 px）。
- 未连接时，流量数字旁/下方必须有"上次会话"字样，明确这是历史数据。

### 1.4 状态矩阵【已确认语义】

| 状态 | 背景 | 图标 | 状态文字 | 流量数字 | 速度 |
| --- | --- | --- | --- | --- | --- |
| 已连接目标热点 | 绿色 | Wi-Fi | 已连接 | 当前会话累计 | 实时 ↓/↑ |
| 未连接 | 红色 | Wi-Fi-off | 未连接 | 上次会话累计（明确标注） | 0 |
| 已连接其他 Wi-Fi | 红色 | Wi-Fi-off | 未连接 | 上次会话累计 | 0 |
| 程序启动、从未有过会话 | 红色 | Wi-Fi-off | 未连接 | `0 B` 或 `--`（待确认） | 0 |
| 采集异常（接口丢失等） | 红色 | 警告（待确认） | 未连接 | 上次会话累计 | 0 |

> 选择"已连接其他 Wi-Fi 也显示红色"的原因：悬浮窗只表达"目标热点是否在用"，不表达"电脑有没有网"。若显示成绿色或"其他网络"，用户会误以为正在统计。

### 1.5 配色【暂定，需对比度校验】

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 已连接背景 | `#1E8E3E`（深绿） | 白字对比度约 4.21:1（满足 WCAG AA 正文 4.5:1 略低，18 px 以上大字号可用） |
| 已连接浅层 | `#34A853` 渐变（可选） | 若要渐变需先确认 |
| 未连接背景 | `#C5221F`（深红） | 白字对比度约 5.80:1 |
| 主文字 | `#FFFFFF` | 不透明 |
| 说明标签 | `#A1A1A6` + `Opacity=0.65` | "已使用流量"；绿底合成约 `#739A82`，对比度 1.34:1，属弱化的装饰性次级文字 |
| 速度文字 | 数值 `#FFFFFF`；箭头 `#D9FFFFFF`；"下载/上传" `#CCFFFFFF` | 竖排两行 |
| 阴影 | 黑色 @ 20%，模糊 8 | 与桌面背景分离 |

禁止使用纯饱和 `#00FF00` / `#FF0000`（刺眼、对比度差）。

### 1.6 字体（阶段 4C-13 现状）

- 胶囊内标签与流量数字统一使用 `Microsoft YaHei UI`（回退 `Microsoft YaHei`），字重同为 `Bold`、样式 `Normal`。
  原因见 §7.10：`Segoe UI Variable` 不含 CJK 字形，此前中文逐字符回退到雅黑、数字留在 Segoe，
  且雅黑只有 Light/Normal/Bold，标签的 SemiBold 被映射成 Bold，造成"标签更粗、字形两套"。
- 数字不再使用 `Segoe UI Variable`：虽然其 Latin 更接近原设计，但无法与中文标签同族。
  字号仍为 46×缩放系数，主体地位不变；未启用 `Typography.NumeralAlignment="Tabular"`（数字宽度变化可接受，
  若后续出现明显跳动再评估）。
- 字号：状态文字 12（当前胶囊已不显示状态文字）；会话数字 46；说明标签 11；速度 14（均随尺寸缩放）。
- 数字变化时不做滚动动画（会干扰读数），仅数值更新。
- 系统字体缺失时的回退链只保留同设计的雅黑家族，不再把 Segoe 放在前面，避免重新引入逐字符混排。

### 1.7 交互【已确认】

- 左键按住**空白区域**拖动整个窗口（固定状态下无效）。
- 右键弹出菜单：
  1. 流量统计
  2. 设置
  3. 固定位置 / 解除固定（按当前状态切换文案）
  4. 退出程序
- 点击"流量统计"打开独立统计窗口；再次点击时激活已存在的窗口。
- 点击"退出程序"才真正终止后台监控；关闭统计窗口不影响监控。
- 悬浮窗本身没有关闭按钮；如需隐藏只能通过右键菜单（是否增加"隐藏悬浮窗"项待确认）。

### 1.8 绝对禁止出现在悬浮窗的内容【已确认】

- 每日 / 每周 / 每月统计数字
- 历史记录列表
- 流量曲线 / 柱状图 / 环形图
- 套餐余量
- 设置项、日志、调试信息

### 1.9 定位规则【已确认目标，实现待阶段 4 验证】

1. 优先放在主屏任务栏上、开始按钮左侧或右侧的空白区域。
2. 不得遮挡开始按钮、搜索框、Widgets/小组件、托盘图标区。
3. 任务栏在屏幕四周任一方向都应正确处理（上/下/左/右）。
4. 多显示器：默认恢复到上次所在显示器；该显示器不存在时回到主屏。
5. 分辨率/DPI/任务栏高度变化后重新校验：窗口必须完整落在可见工作区内，越界则夹回。
6. 自动定位失败 → 使用上次保存位置；仍不可见 → 主屏工作区右上角安全位置。
7. 用户手动拖动后保存位置；自动定位只在"没有保存位置"或"用户点击重新定位"时执行。

实现约束：不注入 Explorer、不修改系统文件、不用未公开接口。允许读取任务栏窗口矩形（`Shell_TrayWnd`）与 UI Automation 开始按钮信息，但必须能优雅降级。

### 1.10 已知限制（必须如实告知用户）

- 无法真正嵌入 Windows 11 任务栏，只是"看起来在旁边"的独立窗口。
- 任务栏自动隐藏、全屏应用、任务栏被第三方工具改造时，自动定位可能失效，需要手动拖动。

## 2. 独立流量统计窗口

### 2.1 窗口形态【已确认】

- 普通桌面窗口：有标题栏、可最小化/最大化/关闭、可缩放、在任务栏显示。
- 与悬浮窗完全分离，共享同一套监控服务与数据库。
- 关闭 = 隐藏/销毁窗口，**不退出程序**。
- 【暂定】最小尺寸 720×520，默认 900×640；记忆尺寸与位置（可选）。

### 2.2 内容结构【已确认范围 + 暂定布局】

```
┌ 流量统计 ─────────────────────────────────────────┐
│ [今日] [本周] [本月] [历史查询]                     │  ← 顶部范围切换
├───────────────────────────────────────────────────┤
│  今日总计  2.36 GB                                  │
│  下载 2.10 GB     上传 260 MB     连接 4 次 / 1h 12m│  ← 摘要卡片
├───────────────────────────────────────────────────┤
│  日期        下载      上传      合计     次数  时长 │
│  2026-11-12  2.10 GB   260 MB   2.36 GB   4    1h12m│
│  2026-11-11  ...                                   │  ← 每日记录表格
├───────────────────────────────────────────────────┤
│  本周合计 ...     本月合计 ...                      │  ← 周/月聚合
└───────────────────────────────────────────────────┘
```

- **今日**：今日总流量、下载、上传、连接次数、累计连接时长。
- **每日记录**：按日期倒序列出，含下载/上传/合计/连接次数/时长。
- **每周统计**：按自然周（周一为一周开始，待确认）聚合。
- **每月统计**：按自然月聚合。
- **历史查询**：选择起止日期，展示区间汇总与每日明细。
- 数据为空时显示"暂无记录"，不显示 0 值表格。
- 【后续扩展】手机套餐余量卡片（第一版不实现，位置预留但不显示）。

### 2.3 数据展示规则【暂定】

- 单位与悬浮窗一致（1024 进制，KB/MB/GB/TB，最多两位小数）。
- 时间格式：`yyyy-MM-dd`；时长 `1h 12m`，小于 1 分钟显示 `<1m`。
- 表格数字右对齐、使用等宽数字。
- 所有数值来自同一数据源，界面不做二次累加，避免与悬浮窗不一致。

### 2.4 刷新【暂定】

- 窗口打开时加载一次；若后台有新会话数据，通过事件通知增量刷新（阶段 5 决定）。
- 不做高频刷新（统计窗口不需要秒级更新）。

## 4. 通用视觉规范【暂定】

- 圆角：胶囊 = 高度/2；卡片 = 8；按钮 = 4。
- 间距基数 4 DIP：4 / 8 / 12 / 16 / 24。
- 统计窗口配色：浅色主题，背景 `#F7F8FA`，卡片 `#FFFFFF`，主文字 `#1F2329`，次级文字 `#646A73`，强调色 `#1E8E3E`。
- 深色主题与跟随系统主题列为后续增强，不在第一版范围。

## 5. 文案与口径

- 悬浮窗与统计窗口都必须能访问到统计口径说明（设置 → 关于，或统计窗口底部小字）：
  > 统计的是本机目标 Wi-Fi 网卡的收发字节，包含协议开销，不含手机自身及其他设备的流量，与运营商计费可能不同。
- 禁止文案："精确计费"、"与移动账单一致"、"零误差"。

## 6. 待确认清单

3. 从未有过会话时显示 `0 B` 还是 `--`。
4. 采集异常时是否使用独立图标/文案。
5. 统计窗口默认范围、周起始日（周一/周日）。
6. 是否记忆统计窗口尺寸位置。
7. 是否需要"隐藏悬浮窗"菜单项与托盘图标。

## 7. 阶段 4C 实现状态（覆盖上文暂定项）

> 以下为已经构建、实机运行并写入自检日志的事实；与上文早期"待确认"冲突时，以本节为准。

### 7.1 悬浮胶囊

- 尺寸：标准 320×104 DIP，圆角 20；预设迷你 220×71.5 / 小型 280×91 / 标准 320×104 / 大型 400×130；
  自定义范围 220–480 × 71.5–156，宽高比固定 320 : 104（容差 1.2%）。全部视觉量由同一个缩放系数派生。
- 结构（阶段 4C-11，基于 4C-8 精简版）：不显示 Wi-Fi 图标与连接状态（由底色表达）；左侧为
  "已使用流量"小标签 + 会话累计流量数字（标准档 46 DIP，随尺寸等比）。二者放在同一个垂直 `StackPanel` 中，
  都 `HorizontalAlignment=Left`，左边缘由同一布局基准决定（不使用 Margin/绝对定位模拟对齐）；标签在数字正上方。
  右侧 ↓ 下载 / ↑ 上传两行竖排实时速度（下载在上、上传在下）。
  流量数字放在 `Viewbox`（只缩小、不裁切），长文本如"999.9 GB"仍完整显示。
- 说明标签（4C-11/4C-12/4C-13）：字号 11×缩放系数、`TextSecondary #A1A1A6`、`Opacity=0.65`（只加在 `TrafficCaption`
  自身，不作用于父容器）、`FontWeight=Bold`、与数字间距 2×缩放系数 DIP；
  与数字共用 `TrafficFontFamily`（`Microsoft YaHei UI, Microsoft YaHei`，中英文均来自同一字体文件，无逐字符回退）。
  自动适配的 Compact/Minimal 密度因高度不足隐藏该标签，Normal 密度与普通四档/自定义尺寸始终显示。
- 对齐（阶段 4C-6）：流量数字与速度块放在**同一个 Grid 行的同一行高**里，二者都是
  `VerticalAlignment="Center"`，因此速度块整体中心严格等于流量数字控件的中心；不依赖任何手工 Margin。
  四档 + 自定义尺寸均由 `UiDump.CheckSpeedAlignment` 断言（容差 0.5 DIP），实测偏差 ≤0.33 DIP。
- 连不上热点时左侧显示"上次 {流量}"，不显示连接状态文字；`_` 表示从未有会话。
- 四档均通过"文本全在窗口内且互不重叠"的矩形断言（`layout=ok texts=8`）。
- 颜色：胶囊背景仍按连接状态使用绿色 `#1E8E3E` / 红色 `#C5221F`（连接状态只保留背景语义）；
  文字 `#F5F5F7`，说明标签 `#A1A1A6 @ 65%`，速度数值纯白、箭头/中文标签带 80%–85% 白透明度。

### 7.2 右键菜单（现行）

1. 流量统计（未实现，禁用）
2. 固定位置 / 解除固定位置（文案随状态变化）
3. 调整大小…（打开设置窗口）
4. 退出程序

设置入口已按要求移到托盘，胶囊菜单不再含"设置"。`ContextMenu` 自身使用
`CapsuleContextMenuStyle` 替换系统模板（背景 `#1F1F23`、1 DIP `#3A3A3F` 边框、圆角 8），
`MenuItem` 与 `Separator` 分别在 `ContextMenu.Resources` 中定义隐式深色样式；
仍不使用 `ItemContainerStyle`（会再次触发 `Separator` 类型冲突，见 D-055、D-063）。

### 7.3 系统托盘

- 使用 WinForms `NotifyIcon` + 自绘深色 `ContextMenuStrip`；图标取自 `Assets/HotspotMeter.ico`。
- 菜单：设置 / 显示悬浮胶囊 / 隐藏悬浮胶囊 / 退出程序；左键双击打开设置。
- 隐藏只隐藏窗口，`MonitorEngine` 继续采样；只有"退出程序"才停止引擎。

### 7.4 设置窗口

- 780×620（最小 740×580），独立窗口、单实例；入口只在托盘与胶囊"调整大小…"。
- 三张卡片：悬浮胶囊外观（四预设 + 自定义宽高 + 预览 + 校验文案）、悬浮胶囊行为
  （固定状态、恢复默认位置、自动适配任务栏开关与检测结果）、程序（启动时显示胶囊）。
- 所有更改立即应用并写入 `%LOCALAPPDATA%\HotspotMeter\ui-state.json`；窗口位置单独记忆。

### 7.5 自动适配任务栏（阶段 4C-8 / 4C-9 修订）

- 开启后自动计算尺寸；**首次开启或从关到开时**定位到当前显示器底部任务栏偏左，之后位置以用户拖动为准，
  启动只恢复保存位置、不重新定位；不扫描任务栏按钮、不自动避让。
- 自动定位（仅底部任务栏）：`X = 显示器左边界 + 120 DIP`（左右各留 8 DIP 夹取），
  `Y = 任务栏顶 + (任务栏高 − 胶囊高)/2`，上限 `显示器底 − 胶囊高`；垂直方向不扣 8 DIP，否则会被顶回任务栏上方。
  顶部/左侧/右侧任务栏返回"不支持自动定位"，不擅自换边。
- 自动适配开启时拖动边界为显示器物理边界（0 DIP 边距），允许拖入任务栏矩形；关闭后恢复工作区 + 8 DIP 夹取。
- 固定位置与自动适配可同时成立：位置锁定，尺寸仍随任务栏变化；拖动结束后只重算尺寸并保存实际位置。
- 检测来源：`SHAppBarMessage(ABM_GETTASKBARPOS)` + `ABM_GETSTATE` + `MonitorFromWindow` + `GetMonitorInfo`
  + `GetDpiForMonitor`（失败退 `GetDpiForWindow`）；失败时回退主屏工作区推断，不崩溃、不抛异常。
- 尺寸算法（`TaskbarSizingCalculator`）：横向任务栏取任务栏实际厚度、纵向取工作区高度，减去 4 DIP 呼吸空间，
  再夹在 40–104 DIP；宽度 = 高度 × 320/104，并以工作区宽减 16 DIP 封顶（最小 132 DIP）。
  密度：≥88 DIP 正常排版，≥56 DIP 紧凑，<56 DIP 最简（隐藏"下载/上传"文字标签，保留 ↓/↑ 与数值）。
  任务栏厚度 <44 DIP 时 `FitsTaskbar=false`，说明文字会明确写出"低于可读下限"。
- 手动尺寸偏好独立保存（`ManualWidth/Height/Left/Top`）；关闭自动适配恢复原尺寸，自动模式不碰用户的
  `Width/Height` 偏好，两种模式配置不互相污染。
- 监听 `WM_SETTINGCHANGE(SPI_SETWORKAREA)`、`WM_DISPLAYCHANGE`、`WM_DPICHANGED` 与 `TaskbarCreated`，
  600 ms 防抖后重算；`TaskbarCreated` 额外重检测、重定位与重断言置顶，并写入 `logs/app.log`。
- 当前实机检测：底部任务栏、150%、工作区 1707×1019 DIP、任务栏厚 48 DIP → 胶囊 135.4×44 DIP（最简排版），
  自动定位 `(120, 1020.7)`，完整落在任务栏 `0,1528,2560,1600` 内。
- 已知限制：任务栏低于 44 DIP 时无法在保持完整可读信息的前提下完整适配；任务栏激活后仍可能短暂遮挡，
  独立窗口没有原生任务栏组件的层级契约。

### 7.8 说明标签与数字的实测几何（阶段 4C-13）

标准档 320×104、150% DPI，UiDump 实测（窗口内 DIP 坐标，文本为 `18.26 KB`）：

| 元素 | 位置/尺寸 |
| --- | --- |
| "已使用流量" | x=18, y=19.3, 54.7×14，字号 11，Bold |
| 流量数字 | x=18, y=35.3, 183.3×48.7，字号 46，Bold |
| ↓/↑ 速度块 | y=39..80.3，中心 59.67 |

- 标签与数字左边缘均为 x=18，严格对齐（UiDump `captionLeftAligned delta=0`）。

### 7.9 说明标签不透明度（阶段 4C-12）

- 实现：`TrafficCaption` 自身 `Opacity="0.65"`；`TrafficValue`、`SpeedBlock` 与父 `StackPanel` 均保持 1.0。
- 断言：`UiDump.CheckSimplifiedContent` 输出 `captionOpacity=0.65 trafficOpacity=1.00 opacityIsolated=True`，
  并检查父容器 `Opacity>=0.999`；四档 + 自定义 + 长文本 + 自动适配全部通过。
- 实测合成色（灰 `#A1A1A6` × 65% 叠在底色上）与 WCAG 对比度：
  - 绿底 `#1E8E3E` → `#739A82`，**1.34:1**（实心灰本身也只有 1.63:1；这是"柔和次级文字"的刻意取舍）
  - 红底 `#C5221F` → `#AE7577`，**1.55:1**（实心灰 2.25:1）
- 约束：不再往下调（0.5 时约 1.2:1，11 px 下会难以辨认）；若实际观感太弱，优先升到 0.75–0.8，
  而不是改数字或父容器。4C-12 本身未改字体、字号、字重、位置；字体家族与字重在 4C-13 统一调整。

### 7.10 字体统一与中英混排回退（阶段 4C-13）

- 现象：标签是中文、数字是拉丁字符，虽共用同一个 `FontFamily` 字符串，实际观感是两套字形，标签还更粗。
- 根因（已由字体表实测确认，不是猜测）：
  1. 资源原值 `Segoe UI Variable Display, Segoe UI, Microsoft YaHei UI` 中，`Segoe UI Variable Display` 的
     `CharacterToGlyphMap` 不含 CJK 字形。WPF 对中文逐字符回退到后备列表里的雅黑，数字/字母仍用 Segoe，
     于是同一个 TextBlock 内出现两种字体。
  2. `Microsoft YaHei UI` 只有 Light(290)/Normal(400)/Bold(700)，没有 SemiBold。标签的 `SemiBold(600)`
     被就近匹配到 Bold，而数字的 Segoe Variable 有真正的 SemiBold(600)，造成"标签比数字粗"。
- 修复：`TrafficFontFamily` 改为 `Microsoft YaHei UI, Microsoft YaHei`（同一字体文件同时含中文与拉丁字形），
  标签与数字都显式 `FontWeight="Bold"`，`FontStyle` 均为 Normal；字号、间距、左对齐、透明度、速度区不变。
- 验证：UiDump 新增 `captionWeightMatch`、`captionStyleMatch`、`fontCoversCjk`、`fontCoversDigits`
  （直接查 `Typeface.TryGetGlyphTypeface` 的字符映射，确认 `已/流/0/B` 都在同一字体文件里），四档/自定义/长文本
  全部 `ok=True`；像素截图标签主色仍为 65% 合成色。
- 代价：数字改用雅黑后，同字号下拉丁字形更宽（标准档 `18.26 KB` 宽 183.3 vs 146.7）、行高更矮（48.7 vs 54），
  视觉比原 Segoe 略宽扁；这是"中英文必须同族"的取舍。若未来允许内嵌字体，可换成同时具备中文与 SemiBold 的开源字体。
